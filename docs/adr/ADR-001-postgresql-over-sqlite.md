# ADR-001. PostgreSQL замість SQLite

Статус: прийнято, 2026-10-11

## Контекст

Система імпортує GTFS-дані, зберігає версії розкладів, підтримує підписки та виконує пошук по маршрутах і зупинках. Необхідна підтримка індексів, транзакцій і складних запитів.

## Розглянуті варіанти

### 1) SQLite

Переваги:
- проста конфігурація;
- не потребує окремого сервера;
- зручна для невеликих проєктів.

Недоліки:
- обмежена підтримка конкурентного доступу;
- гірша масштабованість;
- складніше наблизити середовище до production.

### 2) PostgreSQL

Переваги:
- повноцінна СУБД;
- розвинена підтримка індексів;
- транзакційність;
- хороша інтеграція із SQLAlchemy.

Недоліки:
- потребує окремого сервера;
- складніше розгортання.

## Рішення

Використовувати PostgreSQL як основну базу даних.

## Наслідки

### Позитивні

- підтримка транзакцій;
- можливість оптимізації запитів індексами;
- ближче до production-середовища.

### Негативні

- складніше налаштування локального середовища;
- залежність від контейнера PostgreSQL.

## Умова перегляду

Рішення може бути переглянуто, якщо проєкт стане повністю локальним і перестане потребувати багатотабличних запитів та конкурентного доступу.
