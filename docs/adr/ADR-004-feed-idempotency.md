# ADR-004. Ідемпотентність імпорту GTFS через checksum

Статус: прийнято, 2026-10-11

## Контекст

Постачальник даних може багаторазово надавати однаковий GTFS-фід. Повторна обробка однакового набору даних призведе до створення зайвих версій розкладу та дублювання даних.

Необхідно визначити спосіб виявлення повторних імпортів.

## Розглянуті варіанти

### 1) Завжди створювати нову версію

Переваги:
- проста реалізація;
- не потребує додаткової перевірки.

Недоліки:
- накопичення дубльованих даних;
- зайве навантаження на базу даних;
- складніше порівняння версій.

### 2) Порівнювати контрольну суму архіву

Переваги:
- швидке виявлення дубльованих імпортів;
- відсутність дубльованих версій;
- проста реалізація.

Недоліки:
- додатковий етап обчислення checksum;
- будь-яка зміна архіву створює нову контрольну суму.

## Рішення

Для кожного GTFS-архіву обчислювати SHA-256 checksum та не створювати нову версію розкладу, якщо така checksum вже існує.

## Наслідки

### Позитивні

- усуваються дубльовані імпорти;
- виконується вимога ідемпотентності;
- зменшується обсяг даних.

### Негативні

- необхідно зберігати checksum;
- потрібна перевірка перед імпортом.

## Умова перегляду

Рішення переглядається, якщо джерело почне надавати власні версії або унікальні ідентифікатори наборів даних.
