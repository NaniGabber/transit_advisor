# ADR-003. Потоковий імпорт GTFS

Статус: прийнято, 2026-10-11

## Контекст

GTFS-фіди можуть містити десятки або сотні тисяч записів. Завантаження всього файлу в пам'ять збільшує споживання ресурсів і ускладнює обробку великих наборів даних.

## Розглянуті варіанти

### 1) Повне завантаження файлів у пам'ять

Переваги:
- простіша реалізація;
- зручніше налагодження;
- легше виконувати міжрядковий аналіз.

Недоліки:
- високе споживання пам'яті;
- ризик проблем при великих обсягах даних.

### 2) Потокове читання через ітератори

Переваги:
- стабільне використання пам'яті;
- можливість працювати з великими файлами;
- краща масштабованість.

Недоліки:
- складніша реалізація;
- складніше повторно обробляти записи.

## Рішення

Обробляти GTFS-файли послідовно через `csv.DictReader` та ітератори без завантаження всього файлу в пам'ять.

## Наслідки

### Позитивні

- нижче споживання пам'яті;
- можливість імпорту великих фідів;
- виконання вимог проєкту щодо демонстрації потокової обробки.

### Негативні

- складніше відстежувати помилки;
- неможливо випадково звернутися до довільного запису без повторного читання.

## Умова перегляду

Рішення може бути переглянуто, якщо обсяг імпортованих даних стане незначним або виникне потреба в складній міжрядковій обробці всього набору даних одночасно.
