# ADR-007. Пагінація через LIMIT та OFFSET

Статус: прийнято, 2026-10-11

## Контекст

Система надає пошук маршрутів та зупинок через REST API. Необхідно обмежити кількість записів у відповіді та забезпечити посторінковий перегляд результатів.

## Розглянуті варіанти

### 1) LIMIT/OFFSET

Переваги:
- проста реалізація;
- добре підтримується SQLAlchemy;
- легко пояснюється користувачу.

Недоліки:
- продуктивність погіршується для великих зміщень;
- можливі пропуски та дублікати записів при зміні даних.

### 2) Курсорна пагінація

Переваги:
- стабільні результати;
- краща продуктивність на великих вибірках.

Недоліки:
- складніша реалізація;
- неможливість швидко перейти на довільну сторінку.

## Рішення

Використовувати LIMIT/OFFSET для всіх пошукових ендпоїнтів.

## Наслідки

### Позитивні

- проста реалізація;
- зрозумілий інтерфейс API;
- менше складності в коді.

### Негативні

- менш ефективна робота на дуже великих вибірках;
- можливі нестабільності при активній зміні даних.

## Умова перегляду

Рішення переглядається, якщо обсяг даних суттєво збільшиться або з'являться проблеми продуктивності під час пошуку.
